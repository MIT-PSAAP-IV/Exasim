# Model contract

Reference for the `Model` C++ struct that Exasim's templated FEM internals
consume: every method, every signature, defaults, and indexing layouts.

Exasim's FEM internals (HDG residual assembly, GMRES solver, preconditioner,
time stepping, visualization, QoI integration) are parameterized on a
user-supplied `Model` type. The model is a plain C++ struct that satisfies the
contract in `<exasim/model.hpp>`. It can be **hand-written** or **generated by
`text2code`** from a `pdemodel.txt` description — both paths produce the same
struct shape, and all three usage modes (built-in, external built-in, shared
library) ultimately satisfy this same contract.

!!! note "Mathematical background"
    Each contract method corresponds to a term in the DG/HDG formulation. The
    Theory section will be cross-linked here so every method maps back to the
    equation it supplies.

## The Model contract

A user model is a plain C++ struct with a small set of compile-time constants
and `KOKKOS_INLINE_FUNCTION static` pointwise methods. Inherit from
`exasim::ModelDefaults<Self>` (CRTP) for zero-fill defaults of the optional
methods.

### Required compile-time constants

```cpp
struct MyModel : exasim::ModelDefaults<MyModel> {
    static constexpr int nd     = 2;       // spatial dimension
    static constexpr int ncu    = 1;       // # primary unknowns
    static constexpr int ncw    = 0;       // # auxiliary scalar fields (the `w` array)
    static constexpr int nco    = 0;       // # auxiliary "other DG" fields (the `v` array)
    static constexpr int nparam = 1;       // # physics parameters (the `mu` array)

    static constexpr auto disc  = exasim::Discretization::HDG;  // or LDG
};
```

### Required pointwise methods

The runtime aborts with a Newton non-convergence if any of these are left as the
default zero-fill — `MyModel` MUST override them:

| Method | Output | Purpose |
|---|---|---|
| `flux`     | `f[ncu*nd]` | volume flux at quadrature point |
| `source`   | `s[ncu]`    | volume forcing term |
| `fbou`     | `fb[ncu]`   | LDG boundary flux (per-`ib` dispatch via `if (ib == 1) ...`) |
| `fbou_hdg` | `fb[ncu]`   | HDG boundary residual (per-`ib` dispatch) |
| `ubou`     | `ub[ncu]`   | imposed boundary value (Dirichlet etc., per-`ib` dispatch) |
| `initu`    | `ui[ncu]`   | initial condition |

### HDG Jacobians (required for `disc = HDG`)

The HDG kernels need pointwise Jacobians. Defaults are zero-fill, which makes the
linearized system zero and Newton fail — for HDG you MUST override:

| Method | Output | Layout |
|---|---|---|
| `flux_jac_uq`        | `f_uq[ncu*nd*Nq]`  | column-major: `f_uq[j*(ncu*nd) + i] = ∂f[i]/∂uq[j]` |
| `flux_jac_w`         | `f_w[ncu*nd*ncw]`  | column-major: `f_w[j*(ncu*nd) + i] = ∂f[i]/∂w[j]`   |
| `source_jac_uq`      | `s_uq[ncu*Nq]`     | column-major |
| `source_jac_w`       | `s_w[ncu*ncw]`     | column-major |
| `fbou_hdg_jac_uq`    | `fb_uq[ncu*Nq]`    | column-major (per-`ib` dispatch) |
| `fbou_hdg_jac_uh`    | `fb_uh[ncu*ncu]`   | column-major (per-`ib` dispatch) |
| `fbou_hdg_jac_w`     | `fb_w[ncu*ncw]`    | column-major (per-`ib` dispatch) |

`Nq = ncu * (1 + nd)` is the size of the `uq` array (primary unknowns plus their
gradients in HDG).

### Volume method signature

```cpp
KOKKOS_INLINE_FUNCTION static
void flux(double f[],
          const double x[],          // [nd]
          const double uq[],         // [Nq]
          const double v[],          // [nco]   (auxiliary odg field)
          const double w[],          // [ncw]
          const double mu[],         // [nparam] physics params
          const double uinf[],       // free-stream values (may be nullptr)
          double t)                  // current time
{
    f[0] = mu[0] * uq[1];
    f[1] = mu[0] * uq[2];
}
```

### Boundary method signature

```cpp
KOKKOS_INLINE_FUNCTION static
void fbou_hdg(double fb[], int ib,
              const double x[],   const double uq[],
              const double v[],   const double w[],   const double uh[],
              const double n[],   const double tau[],
              const double mu[],  const double uinf[], double t)
{
    if (ib == 1) {                 // first boundary tag
        fb[0] = -tau[0] * uh[0];
    }
    // else if (ib == 2) ...
}
```

### Optional methods (zero-fill defaults from ModelDefaults)

`sourcew`, `tdfunc`, `avfield`, `eos`, `eos_du`, `eos_dw`, `fhat`, `uhat`,
`stab`, `vis_scalars`, `vis_vectors`, `vis_tensors`, `qoi_volume`,
`qoi_boundary`, `monitor`, `output`, `initq`, `initwdg`, `initudg`, `initodg`.
Override only what your PDE actually defines.

## Two authoring paths

**Hand-written** — write `model.hpp`/`model.cpp` (or `my_model.hpp`) directly
against `<exasim/model.hpp>`.

**`text2code`-generated** — write a `pdemodel.txt` describing the PDE as
SymEngine expressions, then run `text2code <pdeapp.txt>`; the kernels are emitted
for you.

Both paths produce the same struct shape; the runtime consumes them identically.
How those kernels are packaged and selected — compiled into the installed
built-in library, registered out-of-tree as an external built-in model, or built
into a model shared library by a frontend — is what distinguishes the three
usage modes.
